# design-sync notes — art-saturated

This repo is a **Vite + React + Tailwind web application**, not a packaged design
system. The sync covers a scoped **reusable UI subset** (12 components); the
Firebase-heavy feature panels (CommissionForm, ScheduleManager, StudentsPanel,
EventsSection, MessageThread, AvailabilityManager, DailyPlanner, LessonNotebook,
ProfileSetupModal, MysteryPreferencesPanel, TreeOfLifeConfigurator, CropModal,
DrawingCanvas, BarcodeScanner) were deliberately excluded — they're full
features, not design-system primitives.

## Why the non-default setup

- **Custom entry `ds-entry.jsx` (cfg.entry / --entry).** Every component is an
  `export default`, and the converter's synth entry uses `export *`, which does
  NOT re-export defaults — so `window.ArtSaturated.*` would be empty. `ds-entry.jsx`
  names each component (`export { default as X }`) and also exports the providers
  (MemoryRouter / ThemeProvider / CartProvider / AuthProvider) for the wrapper.
- **Firebase stub (`fb-stub.js` + `tsconfig.ds.json` paths).** `src/lib/firebase.js`
  calls `getAuth(app)` at module-eval; with the Vite env vars undefined under esbuild
  it throws `auth/invalid-api-key` synchronously and crashes the whole IIFE (every
  component then fails `[BUNDLE_EXPORT]`). `tsconfig.ds.json` remaps `firebase/{app,
  auth,firestore,storage,functions}` to `fb-stub.js`, an inert ESM stub. It also
  resolves AuthProvider's `{!loading && children}` gate: the stubbed `onAuthStateChanged`
  fires `null` immediately so children render. NOTE: this means the shipped bundle's
  Firebase is inert — components render logged-out / empty; fine for mockups.
- **CSS = compiled Tailwind (`ds-compiled.css`), NOT the dist build.** The Vite dist
  CSS has a content-hashed filename that changes per build. Regenerate the stable copy:
  `./node_modules/.bin/tailwindcss -i ./src/index.css -o ./.design-sync/ds-compiled.raw.css`,
  then prepend the Google Fonts `@import` (see ds-compiled.css line 1) and drop `.raw`.
  Re-run this whenever component Tailwind classes change.
- **Fonts are remote** (Playfair Display + DM Mono via a Google Fonts `@import` at the
  top of ds-compiled.css) → validate prints `[FONT_REMOTE]`, expected. They load at
  runtime, not shipped locally.

## Known render warns (expected — not new)
- `[FONT_REMOTE] "DM Mono", "Playfair Display"` — remote webfont @import, intentional.
- `[GRID_OVERFLOW]` resolved via cfg.overrides: EnigmaField + StylePicker = `column`,
  Toast = `single`/primaryStory Visible, Navbar = `single` @ 1280x80.

## Component-specific
- **ArtCarousel** — floor card by design. It self-fetches recent art from Firestore
  (no props); with the stub that returns empty → component returns `null`. Can't be
  previewed in isolation. It's still importable/usable in the bundle.
- **Navbar / ProfileAvatar** — render the logged-out state (stub user = null).
  ProfileAvatar shows the `?` initials placeholder. Both wrap in `<AuthProvider>` inside
  their preview .tsx (the global wrapper is only Router > Theme > Cart).
- **Toast** — `position: fixed`; previews wrap it in a `transform: translateZ(0)` Stage
  so it stays inside the card.

## Re-sync risks (watch-list)
- **fb-stub.js export set is hand-maintained.** It currently covers the full union of
  `firebase/*` named imports across `src/`. If a NEWLY-synced component's graph imports
  a firebase function not in the stub, esbuild fails with "No matching export '<name>'" —
  add it to fb-stub.js.
- **ds-compiled.css is a build input**, regenerated by hand (tailwind), not by the
  converter. Rebuild it before re-syncing if component classes changed, or stale styles
  ship.
- **Playwright 1.55.0 pins Chromium build 1187** (already cached at
  %USERPROFILE%/AppData/Local/ms-playwright). If that cache changes, re-match the
  playwright version (see base SKILL §4.1).
- **Preview product data is inline + illustrative** (emoji placeholders, no live image
  URLs) — intentional, keeps captures offline-stable.
- **No git repo** detected at the project root at first sync — durable sync inputs
  (.design-sync/) were not committed automatically; commit them if/when the repo is
  initialized.
